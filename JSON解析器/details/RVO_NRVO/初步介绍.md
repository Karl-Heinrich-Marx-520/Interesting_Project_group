# 深度详解：RVO / NRVO 触发条件、标准规则、什么时候不生效、没生效会怎样
先把核心概念拆开，再给**严格触发条件**、**禁用场景**，最后套到你 `tokenize()` 返回 `vector<Token>` 的实际代码里。

## 一、先分清两个核心概念
### 1. RVO（Return Value Optimization）
**返回匿名临时对象优化**
函数返回一个**没有名字的临时对象**，编译器把临时对象直接构造到**调用方接收变量的内存**里，**完全省去拷贝/移动**。

### 2. NRVO（Named Return Value Optimization）
**具名返回值优化**
函数里先定义一个**有名字的局部变量**，最后 `return 局部变量;`，编译器同样直接把这个局部变量构造到调用方变量内存，**零拷贝、零移动**。

> 日常统称 **复制消除（Copy Elision）**，是C++最核心的返回值性能优化。

---

## 二、C++ 标准版本硬性规则
### C++11 / C++14
**复制消除是「编译器可选优化」**
标准不强制要求编译器必须做，但是 **GCC/Clang/MSVC 默认全开**，正常代码一定会触发。

### C++17 及以后
**强制复制消除（Mandatory Copy Elision）**
满足条件时，**编译器必须做RVO/NRVO，不允许省略优化**，语言标准层面直接规定，和编译器配置无关。

---

## 三、RVO 严格触发条件
满足**全部**：
1. 函数返回**纯匿名临时对象**，没有中间具名变量；
2. 直接 `return 类名{...};` 构造临时返回；
3. 返回类型和接收变量**类型严格一致**，无隐式类型转换。

示例：
```cpp
std::vector<Token> foo() {
    return std::vector<Token>{}; // 匿名临时 → 标准RVO
}

auto v = foo(); // 直接在v的内存上构造临时，无拷贝无移动
```

---

## 四、NRVO 严格触发条件（你代码用的就是这个）
满足**所有条件**才会触发：
1. `return` 的是**函数内部栈上的局部非静态具名变量**；
2. 整个函数**所有 return 分支都返回同一个变量**；
3. 不返回函数参数、不返回 static/全局变量；
4. 无复杂分支跳转导致编译器无法静态确定返回哪个变量。

### 你现在的 tokenize 标准 NRVO 写法
```cpp
std::vector<Token> Lexer::tokenize() {
    std::vector<Token> res; // 局部具名变量
    // 不停 push_back 填数据
    return res; // 单一口径返回同一个局部变量 → 完美NRVO
}

// 调用处
auto tokens = lexer.tokenize();
```
**完全命中NRVO所有条件**：
C++17 强制优化；C++11/14 主流编译器必优化。
👉 直接在 `tokens` 内存上构造 `res`，**没有拷贝、连移动构造都不会执行**。

---

## 五、**直接禁用 RVO/NRVO 的场景（必不触发优化）**
只要命中任意一条，**彻底失去复制消除**，只能走移动/拷贝：

1. **多分支返回不同名字的局部变量**
```cpp
std::vector<Token> foo(bool flag) {
    std::vector<Token> a, b;
    if (flag) return a;
    else      return b;
}
```
编译器没法把两个变量塞进同一个接收内存，**NRVO直接废掉**。

2. 返回 `static` 静态局部变量 / 全局变量
```cpp
std::vector<Token> foo() {
    static std::vector<Token> res;
    return res;
}
```
静态变量在全局数据区，不能复用调用方栈内存，**无优化**。

3. 返回**函数形参**
```cpp
std::vector<Token> foo(std::vector<Token> res) {
    return res;
}
```
形参不在函数局部栈的构造可控范围，**禁用NRVO**。

4. 存在隐式类型转换
返回值类型 和 接收变量类型 有自定义转换，**破坏RVO**。

5. 跨编译单元且无LTO链接时优化
函数定义在别的 `.cpp`，当前编译看不到实现，保守放弃优化；
开 **LTO 链接时优化** 仍可恢复。

6. 手动写 `std::move` 强行破坏 NRVO
**高频踩坑！**
```cpp
std::vector<Token> foo() {
    std::vector<Token> res;
    return std::move(res); // 致命错误！
}
```
一旦加 `std::move`，把具名变量转成右值引用，**直接禁用NRVO**，强制走移动构造。
> 口诀：**局部变量return千万别手动move，会亏性能**。

---

## 六、没触发 RVO/NRVO 时会发生什么？
就算极端情况没优化，也**绝不会深拷贝**：
1. 函数内部构造 `vector<Token> res`；
2. 用 `res` **移动构造**一个临时右值；
3. 再用这个临时**移动构造**外部 `tokens`。

### 重点：vector 移动构造极廉价
`std::vector` 移动只拷贝 **3个指针/整型成员**：
- 数据起始指针
- 元素size
- 容量capacity
**不会拷贝内部每一个 Token**，开销是 O(1)，和空结构体赋值差不多。

👉 对你的业务完全无性能影响。

---

## 七、套回你代码的最终结论
```cpp
static JsonValue parse(const std::string& json_str) { 
    Lexer lexer(json_str); 
    auto tokens = lexer.tokenize(); 
    Parser parser(tokens); 
    return parser.parse(); 
}
```
1. `tokenize()` 返回局部唯一 `res` → **完美NRVO触发**；
2. C++17 强制原地构造，无拷贝无移动；
3. C++11/14 GCC/Clang/MSVC 默认必优化；
4. 就算玄学没优化，也只走 vector 移动，**不深拷贝Token**，性能几乎无损失；
5. **绝对不能写 `auto& tokens`**：临时右值绑普通左值引用编译报错；
6. 也没必要 `const auto&`：多一层间接引用，性能没提升还不优雅。

---

## 八、极简记忆口诀
1. 单变量原路返回 → **必NRVO**；
2. 多分支返不同变量 / static / 形参 / 手动move → **无优化**；
3. 没优化也别怕，**vector返回只会移动，不会深拷贝**；
4. 局部`return var` 千万别加 `std::move`。
