# 超通俗详解：C++ `std::string_view` 字符串视图
专门给**初学者**讲，不用晦涩术语，结合你刚才写的 **JSON解析器** 场景，听完立马懂、会用、避坑。

---

## 一、先用大白话比喻（一秒理解）
### 1. `std::string` 普通字符串
好比**复印一份文件**：
别人有一份原文，你**完整复制一份**，放到自己的本子里。
- 占新内存
- 自己独立拥有这份内容
- 改你的副本，不会影响原文

### 2. `std::string_view` 字符串视图
好比**只给你指原文的页码和起止位置**，**不复印、不拷贝**：
- 不新开内存
- 只是「看着别人的字符串」，自己**不拥有数据**
- 全程**零拷贝**，超快、省内存

一句话总结：
**string 是复制数据；string_view 是借用别人的数据，只做“视图查看”。**

---

## 二、底层到底长啥样？（极简内部结构）
`string_view` 内部**就两个变量**，超级轻量：
```cpp
const char*  ptr;   // 指向原始字符串的起始地址
size_t       len;    // 字符串长度
```
就存**指针 + 长度**，**没有堆内存分配、没有拷贝**。

而 `std::string` 内部：要管理堆内存、容量、大小、引用计数等，重很多。

---

## 三、核心三大特性（必须记牢）
### 1. 绝不拷贝内存
不管你把 `string`、字符串常量、字符数组传给它，**它都只记录地址和长度，不复制一个字符**。
👉 这就是**零开销、高性能**的原因。

### 2. 只读不可修改
`string_view` **只能读，不能改**：
没有增删字符、没有修改内容的接口。
它的定位就是：**只用来查看、遍历、传参，不做修改**。

### 3. 不拥有内存（最关键）
`string_view` **不管理内存生命周期**：
数据是别人的，它只是“借用”。
一旦**原始数据销毁了**，`string_view` 就变成**野指针、悬空引用**，程序崩溃。

---

## 四、string_view 和 string 核心对比
| 特性 | std::string | std::string_view |
|------|-------------|------------------|
| 是否拷贝数据 | 拷贝，占新内存 | 不拷贝，零开销 |
| 是否拥有内存 | 拥有，自己管理 | 不拥有，借用别人 |
| 能否修改内容 | 可以增删改 | 只读，不能改 |
| 内存大小 | 大，堆内存分配 | 极小，仅指针+长度 |
| 生命周期 | 自己独立 | 依赖原始字符串 |
| 适用场景 | 需要存、需要改 | 只读传参、解析、遍历 |

## 五、怎么创建 string_view？
```cpp
#include <string_view>
#include <string>

int main()
{
    // 1. 从字符串常量创建
    std::string_view s1 = "hello";

    // 2. 从 std::string 自动转换
    std::string str = "json test";
    std::string_view s2 = str;

    // 3. 手动指定起始地址和长度
    std::string_view s3(str.data(), 4); // 只看前4个字符

    return 0;
}
```
**自动隐式转换**：`string` 可以直接赋值给 `string_view`，不用手动转。

## 六、常用简单接口（够用版）
用法和 `string` 几乎一模一样，初学者不用重新学：
```cpp
std::string_view s = "abcdef";

s.size();       // 长度
s.empty();      // 是否空
s[0];           // 下标访问
s.data();       // 拿到原始const char*
s.substr(1,3);  // 截取子串（还是视图，不拷贝）
```

## 七、初学者最大坑：生命周期悬空（必看）
### 错误用法（绝对不能写）
```cpp
std::string_view get_view()
{
    // 临时string，函数结束就销毁
    std::string temp = "我是临时字符串";
    return temp;  // 危险！返回后temp销毁，view悬空
}
```
原因：
`temp` 是局部变量，函数结束就释放内存，`string_view` 还指着这块已经销毁的内存 → **野指针、崩溃**。

### 正确用法
保证 **原始数据生命周期 ≥ string_view 的生命周期**：
```cpp
int main()
{
    std::string long_life = "我一直活着";
    std::string_view view = long_life;

    // 全程使用view，long_life直到程序结束才销毁
    return 0;
}
```

**口诀**：**谁给 string_view 提供数据，谁就要活得比它久**。

## 八、结合你 JSON 解析器：为什么我让你改成 string_view？
### 原来用 std::string 的问题
```cpp
class Lexer{
    std::string m_input;
};
```
传入JSON字符串时，**会把整个大JSON文本完整拷贝一份**，浪费内存、浪费时间。

### 改成 string_view 后的好处
```cpp
class Lexer{
    std::string_view m_input;
};
```
1. **零拷贝**：直接指向你外面传入的原始JSON字符串，不复制一个字符
2. **速度更快**：不用堆内存分配、不用拷贝
3. **代码不用改逻辑**：遍历、取值、判断字符全都和string一样
4. **轻量**：Lexer对象占用内存极小

完美适配解析器场景：
**词法分析只读取字符、不修改字符，天生就是 string_view 的最佳使用场景**。

---

## 九、什么时候用 string_view？什么时候不用？
### ✅ 适合用
1. 函数只读传参（不修改字符串）
2. 词法解析、文本遍历、JSON解析
3. 常量字符串、配置文本
4. 需要高性能、减少拷贝的场景

### ❌ 不适合用
1. 需要**修改字符串内容**
2. 需要**保存字符串到类成员，且原始数据随时会销毁**
3. 需要拼接字符串、增删字符

---

## 十、一句话总结
1. `string_view` 是**只读字符串视图**，只存指针+长度，**零拷贝、高性能**。
2. 不拥有内存，**依赖原始字符串生命周期**，防止悬空崩溃。
3. 用法和 `string` 几乎一样，上手零成本。
4. 你的JSON词法分析器**只读不改**，用它是最完美的选择。
